# RedCore

Интернет-магазин компьютерного железа и периферии для Узбекистана с 3D-конфигуратором ПК,
проверкой совместимости, калькулятором FPS, AI-агентами на Gemini, MCP-сервером и оплатой Stripe
(test mode). Языки — русский и узбекский (латиница), цены — в сумах.

> Все 12 этапов плана готовы. Сайт работает «из коробки» без внешних сервисов: встроенный
> Postgres (PGlite), мок-оплата, мок-Telegram и детерминированный AI. Что подключить для
> настоящего запуска — [docs/LAUNCH.md](docs/LAUNCH.md), сценарий показа — [docs/DEMO.md](docs/DEMO.md),
> устройство системы — [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

**Возможности:**

- витрина на RU/UZ: каталог с фасетами, поиск с синонимами, сравнение, избранное, SEO;
- конфигуратор ПК: совместимость в реальном времени, расчёт БП, 3D-сборка с анимациями;
- калькулятор FPS для 20 игр и обратный подбор «хочу N FPS»;
- корзина, промокоды, доставка по 14 регионам, оплата Stripe (test) и при получении;
- скрытая админ-консоль (вход по логину и паролю): заказы, возвраты, товары, склад, аналитика, AI-логи;
- AI-агенты на Gemini и MCP-сервер магазина для внешних AI-клиентов;
- уведомления в Telegram персоналу и покупателям.

## Стек

Next.js 16 (App Router, React 19) · TypeScript · Tailwind CSS v4 · shadcn/ui · next-intl ·
Drizzle ORM · Neon Postgres · three.js / react-three-fiber · Stripe · Better Auth · Gemini ·
MCP SDK v2 · grammY · Turborepo + pnpm · Vitest · Playwright. Docker не используется.

## Структура

```
apps/web             Next.js: витрина, конфигуратор, скрытая консоль, API (MCP, AI, вебхуки)
packages/domain      чистая логика без IO: характеристики (Zod), совместимость, БП, FPS,
                     подбор сборки, раскладка 3D, статусы заказа, деньги
packages/db          схема Drizzle, миграции, клиент Neon/PGlite, seed демо-данных
packages/services    сервисы: каталог, поиск, сборки, заказы и платежи, консоль, FPS,
                     MCP-ключи, AI-данные, уведомления, Telegram
packages/mcp         MCP-сервер магазина: инструменты по scopes, ресурсы, транспорты
packages/ai          агенты на Gemini: шлюз, оркестратор, лимиты, детерминированный режим
packages/i18n        словари RU/UZ, форматирование цен и дат
tooling/3d           пайплайн 3D-моделей (gltf-transform)
tooling/fps          калибровка калькулятора FPS
e2e                  Playwright: витрина, оплата, консоль, 3D, AI, доступность
```

## Требования

- Node.js 24 LTS (`.nvmrc`)
- pnpm 12 (`corepack enable`)
- Аккаунт [Neon](https://neon.tech) — для базы данных (сайт запускается и без неё)

## Быстрый старт

```bash
pnpm install
cp .env.example .env.local
pnpm dev
```

Сайт откроется на http://localhost:3000 и перенаправит на `/ru` или `/uz` по языку браузера.

**Без Neon сайт тоже работает:** если `DATABASE_URL` не задан, при первом запросе поднимается
встроенный Postgres (PGlite, в памяти процесса) с миграциями и демо-каталогом — это занимает
пару секунд, данные сбрасываются при перезапуске. С Neon код и SQL те же.
Стайлгайд дизайн-системы — http://localhost:3000/ru/dev/design (только в dev).

## База данных (Neon)

1. Создай проект в Neon, регион **AWS Europe Central 1 (Frankfurt)** — ближе всего к Ташкенту.
2. Создай ветку `dev` от `main`: `main` — продакшен, `dev` — разработка.
3. В панели ветки `dev` скопируй две строки подключения в `.env.local`:
   - `DATABASE_URL` — **pooled** (хост с `-pooler`), её использует приложение;
   - `DATABASE_URL_UNPOOLED` — прямая, для миграций.
4. Примени миграции и демо-данные:

```bash
pnpm db:migrate
pnpm db:seed
```

Проверка подключения: http://localhost:3000/api/health → `{"ok":true,"db":"connected"}`.

Изменил схему в `packages/db/src/schema` → сгенерируй миграцию `pnpm db:generate` и закоммить её.

Начать dev-базу с чистого листа: `pnpm db:reset -- --yes && pnpm db:seed` (удаляет все данные —
только для ветки `dev`, никогда для `main`).

### Демо-данные

`pnpm db:seed` заливает 199 товаров в 16 категориях (комплектующие, периферия и 8 готовых
сборок), индексы производительности 16 видеочипов и 23 процессоров, 15 зон
доставки по Узбекистану, услуги и промокоды. Seed идемпотентен: повторный запуск обновляет
цены, остатки и характеристики, но не трогает рейтинги и переводы, отредактированные вручную.

- Цены заданы в долларах и пересчитываются в сумы: курс ЦБ РУз на 27.10.2026 (11 862 сум/$) ×
  розничная наценка 15%, с округлением до 10 000. Другой курс: `SEED_USD_UZS_RATE=12500 pnpm db:seed`.
- Каждая готовая сборка проходит проверку совместимости при seed — несовместимая не попадёт в базу.
- Характеристики, важные для совместимости (длина видеокарты, высота кулера, габариты корпуса,
  разъёмы БП), взяты из спецификаций производителей.

Seed и миграции проверяются без БД и Docker: `pnpm --filter @redcore/db test` поднимает Postgres в
WASM (PGlite).

## Конфигуратор

`/ru/configurator` — 9 шагов (корпус → плата → процессор → охлаждение → память → видеокарта →
накопители → блок питания → вентиляторы), выбирать можно в любом порядке. Совместимость, мощность
и итог считаются в браузере тем же движком `@redcore/domain`, что и на сервере.

- Кандидаты размечены «совместим / с замечаниями / несовместим» с причиной; по умолчанию
  несовместимые скрыты (флажок «Только совместимые»).
- Панель проблем — тексты `compat.<code>` на RU/UZ, клик по детали переводит к её шагу.
  Шкала мощности: пиковая нагрузка, рекомендуемый БП и загрузка выбранного БП.
- Черновик хранится в `localStorage`. «Сохранить и поделиться» — server action: сервер заново
  проверяет состав, сохраняет сборку (`builds`, `build_items`) и выдаёт ссылку `/b/<id>` с
  OG-картинкой. По ссылке сборка открывается в любом браузере с текущими ценами, кнопка
  «Открыть в конфигураторе» подставляет её в черновик (`/configurator?build=<id>`).
- PDF: `/api/builds/<id>/pdf?locale=ru|uz` (@react-pdf/renderer, шрифт Inter из
  `apps/web/assets/fonts`, лицензия OFL — там же).
- «Вся сборка в корзину» добавляет позиции в наличии и сообщает, какие пропущены.
- События воронки (`configurator_view`, `build_saved`, `build_shared`, `build_to_cart`,
  `build_pdf`) пишутся в `analytics_events` — для дашборда консоли.
- Вошедший покупатель видит свои сборки в кабинете (`/ru/account/builds`).

## Покупка и аккаунт

- **Вход** `/ru/login` — номер телефона (+998) и пароль; на вкладке «Регистрация» — номер,
  пароль и его подтверждение. Демо-покупатель: `+998 90 123 45 67`, пароль `RedCore-Demo-2026`. Демо-покупатель из seed: `+998 90 123 45 67`.
- **Корзина** `/ru/cart` — промокоды `REDCORE10` (−10% от 5 млн), `WELCOME` (−200 000 на первый
  заказ), `PERIPHERY15` (−15% на периферию).
- **Оформление** `/ru/checkout` — контакты, 15 зон доставки и самовывоз, ориентир для курьера,
  сборка ПК в магазине (если в заказе есть процессор и плата), карта или оплата при получении.
- **Заказ** `/ru/orders/<номер>?token=…` — статус, история, оплата. Гость сохраняет ссылку
  (статусы — в Telegram), вошедшему покупателю заказ виден в кабинете `/ru/account`.
- **Оплата картой** без ключей Stripe работает через мок-шлюз с тестовыми картами Stripe
  (4242 — успех, 3155 — 3-D Secure, 9995 — отказ). Заказ становится «оплаченным» только через
  вебхук — и с настоящим Stripe, и с мок-шлюзом. Подробно — в [docs/PAYMENTS.md](docs/PAYMENTS.md).

В продакшене обязателен `BETTER_AUTH_SECRET` (`openssl rand -base64 32`); локально и в CI
используется запасной dev-секрет.

## Админ-панель

Открывается по секретному пути из `ADMIN_BASE_PATH` (в dev — `/ops-console-dev`), вход —
логин и пароль. Демо: логины `admin` и `manager`, пароль `RedCore-Staff-2026` (задаётся
`SEED_STAFF_PASSWORD`). Роли, защита и разделы — в [docs/ADMIN.md](docs/ADMIN.md).

## 3D

На карточке каждого товара — интерактивная 3D-модель. Пока базовые GLB не скачаны, модели
процедурные: строятся в коде по характеристикам (длина видеокарты, высота кулера, габариты
корпуса). Скачать и собрать модели со Sketchfab: `pnpm assets:fetch && pnpm assets:build`
(нужен `SKETCHFAB_API_TOKEN`, иначе файлы кладутся вручную в `tooling/3d/raw/<ключ>/`).
Бюджеты и лицензии проверяет `pnpm assets:report`.

В конфигураторе над списком деталей — 3D-сборка: выбранная деталь сразу встаёт в корпус с
анимацией, камера перелетает к активному шагу. Режимы: обычный, без боковой панели, разнесённый
вид и подсветка слота; плюс RGB, качество и снимок сборки в PNG. Подробно — [docs/3D.md](docs/3D.md).

## Калькулятор FPS

На `/fps` — оценка FPS в 20 играх для любой пары видеокарта + процессор: разрешение, пресет,
апскейл (DLSS/FSR/XeSS), генерация кадров, ограничитель и диапазон. Режим «Хочу N FPS»
подбирает 2–3 совместимые сборки из наличия и открывает их в конфигураторе; там же — панель FPS
текущей сборки. Игры и замеры правятся в консоли (раздел «Игры», импорт CSV), коэффициенты
калибруются по реальным замерам: `pnpm fps:calibrate`. Методика — [docs/FPS_METHOD.md](docs/FPS_METHOD.md).

## MCP-сервер

Каталог, совместимость, FPS, подбор сборок, заказы, склад и аналитика доступны внешним
AI-клиентам по Model Context Protocol: Streamable HTTP на `/api/mcp` с ключом `rc_…` из
консоли (раздел «MCP») и stdio для Claude Desktop/Cursor (`pnpm mcp:stdio`). Инструменты
видны по scopes ключа, каждый вызов пишется в журнал, заказы создаются только черновиками —
покупатель подтверждает их по ссылке. Подробно — [docs/MCP.md](docs/MCP.md).

## AI-агенты

Плавающий ассистент на сайте, панель в конфигураторе (с «Проверить сборку с AI») и помощник
в консоли. Агенты работают на Gemini через MCP-инструменты с правами пользователя: цены и
товары — только из базы, ответы стримятся, сборки открываются в конфигураторе, замены
применяются одной кнопкой, описания товаров сохраняются черновиками. Без `GEMINI_API_KEY`
сайт работает: ассистент отвечает в детерминированном режиме (подбор по бюджету, статус
заказа, правила магазина). Лимиты, бюджеты токенов и AI-логи — в консоли. Подробно —
[docs/AGENTS.md](docs/AGENTS.md).

## Telegram

Бот присылает в админ-чат новые заказы, оплаты, отмены, возвраты и «заканчивается», а
покупатель по кнопке на странице заказа подписывается на статусы на своём языке. Без
`TELEGRAM_BOT_TOKEN` работает мок: сообщения видны на `/ru/dev/inbox`. Подробно —
[docs/TELEGRAM.md](docs/TELEGRAM.md).

## Переводы

Все тексты интерфейса — в `packages/i18n/messages/{ru,uz}/*.json`. Русский словарь — эталон
структуры: пропущенный в узбекском ключ ловит TypeScript, лишние ключи и расхождения
плейсхолдеров — `pnpm i18n:check` и тесты. В узбекском используем официальную орфографию:
`ʻ` (U+02BB) в oʻ/gʻ и `ʼ` (U+02BC) для тутук белгиси.

## Безопасность

- Заголовки на всех ответах: CSP (Stripe, CDN Steam и R2 — по списку, `object-src 'none'`,
  `frame-ancestors 'none'`), HSTS, `nosniff`, `X-Frame-Options: DENY`, Referrer-Policy,
  Permissions-Policy, COOP. CSP без nonce — чтобы каталог и карточки оставались пререндеренными.
- Консоль — только по секретному пути, логин и пароль, блокировка после 5 попыток, роли, аудит.
- Цены, остатки и совместимость сервер всегда пересчитывает сам; оплата подтверждается только
  подписанным вебхуком.
- AI и MCP работают с правами пользователя, PII в журналах маскируется, записи — только черновики.
- `pnpm audit --prod` — без известных уязвимостей (точечные `overrides` в `pnpm-workspace.yaml`).
