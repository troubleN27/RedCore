# Заказы и оплата

## Поток заказа

1. **Корзина.** Гость хранит корзину и избранное в браузере. После входа они сливаются с аккаунтом
   (по каждому товару берётся большее количество), дальше каждое изменение сохраняется на сервере.
2. **Расчёт.** `quoteCart` (сервисы) и `computeQuote` (домен, без IO) считают подытог, промокод,
   доставку и услуги. Скидка раскладывается по позициям методом наибольшего остатка
   (`allocateByWeights`), поэтому сумма в Stripe совпадает с нашей до сума.
3. **Оформление** — `placeOrder`, одна транзакция:
   - цены и статусы товаров читаются из БД (не из кэша каталога и не от клиента);
   - резерв — условный `UPDATE … WHERE stock_qty - reserved_qty >= qty`: из параллельных покупок
     последней единицы проходит ровно одна (тест «без овер-селла»);
   - промокод: лимиты на покупателя (по телефону и аккаунту) и общий лимит — тоже атомарно;
   - `checkoutAttemptId` защищает от двойного клика: повтор возвращает уже созданный заказ.
4. **Оплата картой** — `startPayment`: Checkout Session (`ui_mode: 'elements'`, валюта `uzs`,
   сумма × 100), срок 31 минута (минимум Stripe — 30), idempotency key `order:{id}:checkout:{n}`.
   Открытая сессия переиспользуется; после истечения создаётся новая попытка.
5. **Вебхук** `/api/webhooks/stripe` — единственное место, где заказ становится «оплаченным».

| Событие                               | Действие                                                  |
| ------------------------------------- | --------------------------------------------------------- |
| `checkout.session.completed` (`paid`) | списание резерва, статус «оплачен», Telegram              |
| `checkout.session.async_payment_*`    | то же для асинхронных способов / отметка неудачи          |
| `payment_intent.payment_failed`       | код отказа в попытке; заказ ждёт оплаты, можно повторить  |
| `checkout.session.expired`            | отмена заказа «время на оплату истекло», резерв снимается |
| `charge.refunded`                     | полный возврат → «возвращён», частичный → статус оплаты   |

Идемпотентность: `stripe_events.id = evt_…` (повтор события — сразу 200) плюс машина состояний
(повторное «оплачено» — no-op). Сумма события сверяется с заказом. Оплата, пришедшая после отмены,
помечается в истории `late_payment_refund_required` — возврат делает менеджер (этап 5).

Если вебхук потерялся, `expireStaleOrders` отменяет просроченные заказы при открытии страницы
заказа (на Vercel Hobby cron — только раз в сутки).

6. **Наложенный платёж.** Резерв при создании; списание — когда менеджер переводит заказ в сборку,
   статус оплаты «оплачен» — при доставке. В Каракалпакстан — только предоплата.

## Режимы оплаты

| Условие                                                                              | Шлюз                          |
| ------------------------------------------------------------------------------------ | ----------------------------- |
| `STRIPE_SECRET_KEY` + `STRIPE_WEBHOOK_SECRET` + `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` | Stripe, форма Payment Element |
| ключей нет, `pnpm dev` или CI                                                        | мок-шлюз                      |
| ключей нет, продакшен, `PAYMENTS_MOCK=1`                                             | мок-шлюз (демо-стенд)         |
| иначе                                                                                | только оплата при получении   |

**Мок-шлюз** не меняет заказ сам: он строит события в формате Stripe, подписывает их тем же
алгоритмом (`stripe.webhooks.generateTestHeaderString`) и отправляет POST-запросом в наш вебхук.
Тестовые карты: `4242 4242 4242 4242` — успех, `4000 0025 0000 3155` — 3-D Secure,
`4000 0000 0000 9995` — недостаточно средств; кнопка «Смоделировать истечение срока».

## Проверка со Stripe (test mode)

```bash
stripe login
stripe listen --forward-to localhost:3000/api/webhooks/stripe
```

`whsec_…` из вывода — в `STRIPE_WEBHOOK_SECRET`, ключи `sk_test_…`/`pk_test_…` — из Dashboard.
Повтор события для проверки идемпотентности: `stripe events resend evt_…`.
Форма Stripe показывается на русском (узбекского языка у Stripe нет), всё вокруг неё — на языке
сайта. Stripe не принимает Uzcard/Humo и не регистрирует мерчантов из Узбекистана — это демо;
для реального запуска нужен Payme, Click или Uzum за тем же интерфейсом `PaymentGateway`.

## Вход и уведомления

Better Auth: регистрация — номер телефона (+998), пароль и подтверждение; вход — номер и пароль,
после 5 ошибок подряд — блокировка на 15 минут. Номер ничем не подтверждается, поэтому гостевые
заказы к аккаунту не привязываются — в кабинете видны заказы, оформленные после входа.
Уведомления — только Telegram и страница заказа; почты и SMS нет. Почту покупателя магазин не
собирает; для оплаты картой её спрашивает форма Stripe (чек Stripe).
