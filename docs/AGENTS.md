# AI-агенты

Пакет `packages/ai` содержит четырёх агентов на Gemini поверх MCP-сервера магазина
(см. [MCP.md](MCP.md)):

- **шлюз моделей** `LlmGateway`;
- **оркестратор** `chat()`;
- **цикл агента** — модель ⇄ инструменты;
- **детерминированный режим** — работа без LLM;
- **лимиты**.

Агенты не ходят в базу сами: любой факт они берут через MCP-инструменты с правами текущего
пользователя.

## Агенты

| Агент          | Где                                                  | Инструменты                                                                                     | UI-действия                                   |
| -------------- | ---------------------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------------------- |
| **consultant** | виджет на сайте, карточка товара, конфигуратор       | поиск, карточка, категории, `generate_builds`, совместимость, FPS, игры, альтернативы, доставка | `propose_build`, `show_products`, `handoff`   |
| **reviewer**   | кнопка «Проверить сборку с AI» в конфигураторе       | совместимость, `analyze_build`, FPS, `suggest_alternatives`, карточка, поиск                    | `propose_swap` (кнопка «Заменить»), `handoff` |
| **support**    | виджет в кабинете и на странице заказа, общий виджет | `get_my_orders`, `get_order_status`, `get_policy`, доставка, `create_support_ticket`            | `handoff`                                     |
| **admin**      | консоль → «AI»                                       | `sales_report`, `low_stock_report`, `purchase_recommendations`, склад, поиск, заказы            | `propose_product_copy` (черновик)             |

**Маршрутизация:**

- По месту в интерфейсе:
  - конфигуратор → консультант;
  - «Проверить сборку» → ревьюер;
  - кабинет и заказ → поддержка;
  - консоль → админ.
- Общий виджет классифицирует первое сообщение моделью Flash-Lite (структурированный enum).
  Без модели — по ключевым словам.
- Если вопрос не по профилю, агент делает `handoff`. Диалог переходит к другому агенту в том
  же ходе (один раз), история сохраняется.

**Промпты** написаны на английском и содержат:

- директиву языка беседы и глоссарий терминов RU → UZ;
- контекст страницы: текущая сборка, открытый товар или заказ, вошёл ли пользователь;
- лимит в 6 шагов.

## Гарантии

**Факты — только из инструментов.** Карточки сборок, замен и товаров строятся сервером по
slug из базы:

- `propose_build` заново проверяет совместимость и сохраняет сборку (`source=ai`);
- `propose_swap` проверяет наличие и совместимость.

**Guard по суммам.** В ответе ищутся все суммы «… сум / soʻm / UZS». Если такой суммы нет ни в
одном результате инструментов:

1. виджет получает `retract`;
2. модель переписывает ответ без инструментов, только с ценами из результатов;
3. в логе запуска ставится отметка `guardRetried`.

**Права.** MCP-сервер агента собирается с scopes пользователя:

| Пользователь | Scopes              |
| ------------ | ------------------- |
| гость        | `guest`             |
| покупатель   | `customer`          |
| персонал     | `manager` / `admin` |

Поэтому «покажи чужой заказ» получает отказ инструмента, а не ответ модели. Это проверено
тестом.

**Запись — только черновики:**

- заказ из чата — черновик с подтверждением покупателем (см. MCP.md);
- описания товаров — `ai_drafts`. Витрина меняется только после «Применить» в консоли, переводы
  получают `source=ai`.

**PII** в журнале вызовов маскируется.

## Шлюз и отказоустойчивость

`GeminiGateway` вызывает `@google/genai` (`generateContentStream`) в stateless-режиме: историю
храним сами (`ai_messages`).

- Функции не вызываются автоматически — их исполняет цикл агента через MCP.
- Ответ стримится.
- `usageMetadata` даёт токены: input / output / thought / cached.

**Модели** задаются в env:

| Переменная           | Значение по умолчанию   | Для чего      |
| -------------------- | ----------------------- | ------------- |
| `GEMINI_MODEL_CHAT`  | `gemini-3.8-flash`      | чат           |
| `GEMINI_MODEL_POWER` | = chat                  | админ-агент   |
| `GEMINI_MODEL_LITE`  | `gemini-3.5-flash-lite` | классификатор |

**Отказы:**

1. 429, 5xx или таймаут 30 с → два повтора (0,3 с, 1,2 с).
2. Затем следующая модель цепочки:
   - chat: `chat → gemini-3.6-flash → lite`;
   - power: `power → chat`.
3. Ошибка запроса (400) → сразу следующая модель.
4. Вся цепочка упала → circuit breaker на 60 с.

Повтор возможен только пока модель ничего не отдала клиенту.

**Детерминированный режим.** Сайт работает и без Gemini. Режим включается, если:

- нет ключа;
- цепь разомкнута;
- AI выключен в консоли;
- исчерпан дневной бюджет токенов;
- модель упала до ответа.

Что отвечает каждый агент в этом режиме:

| Агент       | Ответ без LLM                                                                  |
| ----------- | ------------------------------------------------------------------------------ |
| Консультант | Разбирает бюджет («до 15 млн») и назначение, показывает 3 сборки из подборщика |
| Ревьюер     | Совместимость и `analyze_build` для текущей сборки                             |
| Поддержка   | Статус заказа по номеру и телефону, правила по ключевым словам, «мои заказы»   |
| Админ       | Сводка за 7 дней с графиком                                                    |

Виджет показывает плашку «AI сейчас недоступен».

> **Interactions API.** План (§8) предлагал Interactions API основным путём. Реализован
> `generateContent` за тем же интерфейсом `LlmGateway`: история и так хранится у нас, а
> stateless-стрим с вызовом функций покрывает все сценарии. Перейти на Interactions можно,
> добавив вторую реализацию шлюза.

## Лимиты и наблюдаемость

Значения по умолчанию задаются в консоли → «AI» → «Настройки» (только администратор):

| Ограничение           | Гость                            | Пользователь |
| --------------------- | -------------------------------- | ------------ |
| Сообщений за 10 минут | 20 (по IP)                       | 60           |
| Токенов в сутки       | 60 000 (по cookie `rc_ai_guest`) | 250 000      |

- Длина сообщения — не больше 2000 символов.
- Есть выключатель AI.
- Лимит сообщений считается в Upstash Redis (`UPSTASH_REDIS_REST_*`), без него — окно в памяти
  инстанса.
- Circuit breaker живёт в памяти инстанса.

**Логи** (`ai_runs`) для каждого хода пишут:

- агента, модель и `fallbackFrom` или режим без AI;
- токены, шаги, латентность;
- стоимость в микродолларах (таблица цен — `gateway/pricing.ts`);
- guard, ошибку.

Вызовы инструментов лежат в `ai_tool_calls` с `runId`.

Консоль → «AI» показывает:

- график токенов за 14 дней (в подсказке — ошибки и фолбэки);
- фильтры по агенту и ошибкам;
- просмотр диалога;
- черновики описаний;
- чат админ-агента.

## SSE-протокол — `POST /api/ai/chat`

Тело запроса:

```json
{
  "message": "…",
  "place": "widget|product|configurator|review|account|order|console",
  "conversationId": null,
  "locale": "ru",
  "context": { "buildItems": [{ "slug": "…", "qty": 1 }], "productSlug": "…", "orderNumber": "…" }
}
```

Поток `text/event-stream`, по одному событию на строку `data: {...}`:

| Событие                   | Что значит                                           |
| ------------------------- | ---------------------------------------------------- |
| `meta`                    | id диалога и агент                                   |
| `text-delta`              | кусок ответа                                         |
| `retract`                 | guard: виджет очищает текст ответа                   |
| `tool-start` / `tool-end` | чипы «Проверяю совместимость…»                       |
| `ui`                      | карточки: build, swap, products, copy, chart, ticket |
| `handoff`                 | диалог передан другому агенту                        |
| `fallback`                | ответ без LLM и причина                              |
| `error`                   | ошибка                                               |
| `done`                    | ход завершён                                         |

Ошибки до потока — 400 `too_long` и 429 `rate_limited`.

## Тесты

**`packages/ai/src/ai.test.ts`** — PGlite с seed, сценарный шлюз `ScriptedGateway` вместо
Gemini:

- полный цикл консультанта: подбор → карточка → ответ, журнал запуска и вызовов;
- guard: переписывание ответа;
- handoff консультант → поддержка;
- чужой заказ — отказ;
- консоль только для персонала, черновик описания → применение менеджером;
- детерминированные ответы: без ключа, после сбоя модели, проверка сборки, заказ по телефону;
- выключатель и дневной бюджет;
- шлюз Gemini на подменённом клиенте: повторы на 429, переход по цепочке, 400 без повторов,
  circuit breaker;
- разбор бюджета, лимитер.

**`e2e/ai.spec.ts`** проверяет режим без ключа, как его видит покупатель:

- виджет → 3 сборки → конфигуратор → «Проверить сборку»;
- поддержка;
- узбекский интерфейс;
- ограничение длины.

**`e2e/console.spec.ts`:**

- админ-агент со сводкой и графиком;
- AI-логи и просмотр диалога;
- менеджер не видит настройки.

> **Не проверено вживую:** ответы настоящей модели Gemini. В окружении разработки нет
> `GEMINI_API_KEY`. Цикл с моделью покрыт сценарными тестами. Сценарии из критериев этапа
> («собери ПК для монтажа и игр до 15 млн» на RU и UZ, дисбалансы в 5 сборках) нужно прогнать
> после получения ключа.
