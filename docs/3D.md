# 3D: модели, пайплайн, просмотр

## Как выбирается модель товара

`modelSpecFor(product)` (`@redcore/domain`) превращает характеристики в параметры модели: длину
и толщину видеокарты, высоту кулера, габариты корпуса, число слотов памяти, размер вентилятора,
цвет исполнения и наличие подсветки. Единицы — метры, +Y вверх.

Источник модели по приоритету:

1. **Своя GLB** из админки (`products.model3d.customUrl`).
2. **Базовая GLB** из манифеста (`glbKey` подтипа), если она собрана — `apps/web/src/generated/models.json`.
3. **Процедурная модель** по тем же параметрам (`apps/web/src/three/parts`). Есть для каждого
   подтипа, поэтому 3D работает и без скачанных моделей.

## Пайплайн базовых моделей (`tooling/3d`)

```bash
pnpm assets:fetch     # скачать по манифесту (нужен SKETCHFAB_API_TOKEN)
pnpm assets:build     # собрать LOD0/LOD1 в apps/web/public/models
pnpm assets:report    # бюджеты + ASSETS_LICENSES.md + страница /credits
```

Без токена положите файл вручную: `tooling/3d/raw/<ключ>/model.glb` (ключи и ссылки — в
`ASSETS_LICENSES.md`, раздел «Ожидают скачивания»). `fetch` перепроверяет лицензию: модель не
под CC BY 4.0 пропускается.

`build` для каждой модели:

1. Очистка: prune, dedup, weld.
2. Роли материалов по манифесту:
   - `body_*` — перекрашивается в цвет исполнения;
   - `rgb_*` — подсветка;
   - `glass_*` — стекло.
3. Масштаб к реальному габариту детали (метры) и центрирование.
4. Упрощение meshoptimizer до целевого полигонажа: LOD0 и LOD1.
5. Текстуры WebP: 2048 px для LOD0, 512 px для LOD1.
6. Сжатие `EXT_meshopt_compression`.

Частичная сборка: `pnpm assets:build gpu_3fan`.

**Бюджеты** (`assets:report` падает в CI при превышении):

| Что                 | Предел                      |
| ------------------- | --------------------------- |
| LOD0 одной модели   | 1 МБ                        |
| LOD1 одной модели   | 300 КБ                      |
| Треугольники        | целевые из манифеста + 10%  |
| Сцена конфигуратора | 8 МБ десктоп / 3 МБ телефон |

## Просмотр на карточке товара

- Сцена грузится отдельным чанком, только когда блок попал в экран. До этого показывается
  обычная иллюстрация. Вне экрана кадры не рисуются (`frameloop="never"`).
- Управление: вращение, масштаб и сдвиг, автовращение (выключено при `prefers-reduced-motion`),
  сброс вида, цвет исполнения, включение и цвет RGB, выбор качества.
- Камера ставится по описывающей сфере модели — любая деталь целиком в кадре.
- Освещение студийное, процедурное (лайтформеры с красным контровым светом), без внешних
  HDRI. Тонмаппинг AgX.

**Качество** определяет detect-gpu: бенчмарки лежат в `public/detect-gpu`, внешний CDN не нужен.
`PerformanceMonitor` понижает уровень на лету.

| Уровень | Настройки                                                             |
| ------- | --------------------------------------------------------------------- |
| high    | DPR ≤ 2, мягкие тени, bloom, стекло с пропусканием света, MSAA        |
| medium  | DPR 1,5, тени, bloom, простое стекло                                  |
| low     | DPR 1, без теней и постобработки, LOD1, перерисовка только по запросу |

**Устойчивость:**

- при потере WebGL-контекста Canvas пересоздаётся;
- без WebGL остаётся иллюстрация с пояснением;
- битая GLB заменяется процедурной моделью.

## Своя модель из админки

Карточка товара в консоли → «3D-модель» → «Загрузить GLB». Файл проверяется на сервере:

- сигнатура GLB;
- разбор glTF, включая расширения meshopt и Draco;
- до 15 МБ и 500 000 треугольников.

Масштаб к размеру детали сцена приводит сама. Хранилище:

- **Cloudflare R2** (заданы `R2_*`): браузер получает presigned-ссылку и грузит файл прямо в
  бакет, минуя лимит тела запроса функции Vercel (4,5 МБ). Затем сервер скачивает файл, проверяет
  его и привязывает к товару.
- **Без R2** (dev, демо): файл хранится в таблице `models_3d` и отдаётся с
  `/api/models/<id>`.

Каждая загрузка и удаление пишутся в журнал действий.

## 3D-сборка в конфигураторе

Блок «3D-сборка» над списком деталей повторяет черновик из store. Новая деталь сразу встаёт в
корпус, замена отражается в сцене в том же рендере: в E2E меньше 300 мс от клика, анимация идёт
следом.

**Раскладка** — `layoutBuild(build)` в `@redcore/domain` (`assembly.ts`), чистая функция с тестами:

- **Оси корпуса:** начало координат в центре, +X — к передней панели, +Y — вверх, +Z — к стеклу.
  Единицы — метры.
- **Плата** лежит на стойках поддона, её верхний задний угол — у выреза I/O.
- **Разъёмы платы** задаёт `boardFeatures()`: сокет, DIMM, PCIe, M.2. По тем же координатам
  рисуется процедурная плата, поэтому процессор и память попадают точно в слоты.
- **Память** ставится по порядку заполнения из мануалов: два модуля — в A2 и B2.
- **СЖО** собирается из двух частей: помпа на сокете, радиатор под верхней панелью. Верхние места
  под вентиляторы при этом заняты.
- **Накопители:** NVMe — в разъём M.2 под углом 20°, SATA — в отсеки у передней стенки.
- **Вентиляторы** занимают места по порядку: перед → верх → тыл.
- **Векторы установки.** У каждой детали есть `installFrom` — откуда она въезжает. Для неё же
  считается пресет камеры.
- **Деталь, выходящая за корпус** (`fitsInCase`), обводится красным контуром. Это тот же случай,
  о котором сообщает движок совместимости.

**Сцена** (`apps/web/src/three/configurator`):

| Файл                 | Что делает                                                                      |
| -------------------- | ------------------------------------------------------------------------------- |
| `case-shell.tsx`     | Корпус отдельными стенками; боковая панель снимается — уезжает к зрителю и тает |
| `orient.tsx`         | Повороты из осей процедурных моделей в оси корпуса                              |
| `assembly-parts.tsx` | Детали с «присутствием», анимации, разнесённый вид, «призрак», шланги СЖО       |
| `assembly-scene.tsx` | Canvas, свет, перелёты камеры (CameraControls), снимок PNG, статистика          |

**Анимации** работают в `useFrame`, без отдельной библиотеки таймлайнов:

- **Установка:** деталь въезжает по вектору установки за 0,6 с с лёгким дожимом в конце.
- **Замена:** старая деталь выезжает за 0,4 с, новая въезжает следом.
- **Смена корпуса или платы:** детали плавно переезжают на новые места.
- В режиме «по запросу» (low) кадры рисуются только во время движения.
- При `prefers-reduced-motion` всё встаёт на место сразу: камера не перелетает, панель не
  анимируется.

**Режимы вида:**

| Режим      | Что видно                                                                                                                |
| ---------- | ------------------------------------------------------------------------------------------------------------------------ |
| Обычный    | Корпус со стеклом                                                                                                        |
| Без панели | Боковая панель снята                                                                                                     |
| Разнести   | Детали расходятся слоями вдоль векторов установки, плата остаётся на поддоне. Подпись — у активного шага и при наведении |
| Подсветка  | Активный слот в полном цвете, остальное полупрозрачно                                                                    |

**Камера** при смене шага перелетает к крупному плану слота. Кнопка «Обзор» показывает корпус
целиком. Пустой обязательный слот активного шага подсвечивается красным «призраком».

**Ещё:** RGB (вкл/выкл и цвет), выбор качества, снимок сборки в PNG. Сцена — отдельный чанк,
грузится, когда блок попал в экран. Без WebGL показывается пояснение. После потери контекста
Canvas пересоздаётся.

**Ресурсы GPU.** Материалы создаются по одному набору на цвет исполнения, а не на деталь.
Геометрии вентиляторов и рёбер кулеров слиты и освобождаются при размонтировании. После 50 замен
видеокарты число геометрий и текстур не растёт — это проверяет `e2e/assembly.spec.ts` через
`window.__redcoreAssembly`.

**Замеры** (сборка из 9 слотов, 82 меша):

| Условия                                     | Результат                                      |
| ------------------------------------------- | ---------------------------------------------- |
| GTX 1660 Super, 1440×900 и эмуляция Pixel 7 | Стабильно 60 FPS (vsync) на high, medium и low |
| Low на телефоне                             | 78 вызовов отрисовки, ~20 тыс. треугольников   |
| Программный рендер SwiftShader (CPU), low   | ~27 FPS — заведомо хуже любого мобильного GPU  |

Своих ассетов сцена не грузит: модели процедурные, а вес 3D — это только JS-чанк three.js и
сцены.

Базовые GLB из пайплайна пока используются только в просмотре товара. В сборке нужны узлы
`mount` и якоря из манифеста (план, §11) — их подключим, когда модели будут скачаны.
