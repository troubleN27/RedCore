# Калькулятор FPS: методика

Калькулятор показывает **оценку**, а не замер. На сайте это видно везде: бейдж «Оценка»,
тултип с методикой, диапазон рядом с цифрой.

## Формула

Эталоны:

- видеокарта — **RTX 5070**, индекс 1.00 по каждому разрешению;
- процессор — **Ryzen 7 9800X3D**, индекс 1.00.

Код — `packages/domain/src/fps`.

```
FPS_GPU = G[игра, разрешение, пресет] · I_gpu[разрешение] · bias[игра, вендор] · U[разрешение, апскейл]
FPS_CPU = C[игра, пресет] · I_cpu^α[игра] · M_ram
FPS     = (FPS_GPU^-k + FPS_CPU^-k)^(-1/k) · P_vram · P_ram          k = 5 («мягкий минимум»)
FPS_FG  = FPS · F[режим]                                              отдельной цифрой
```

**Обозначения:**

| Символ  | Что это                                                                                      |
| ------- | -------------------------------------------------------------------------------------------- |
| `G`     | FPS эталонной карты без упора в процессор: 3 разрешения × 4 пресета                          |
| `C`     | Потолок эталонного процессора по пресетам                                                    |
| `I_gpu` | Индекс карты, свой для каждого разрешения (масштабирование в 4K другое) — таблица `perf_gpu` |
| `I_cpu` | Игровой индекс процессора — таблица `perf_cpu`                                               |
| `α`     | Чувствительность игры к процессору, 0.5–1. У киберспорта ≈ 1, у тяжёлых AAA ≈ 0.6–0.7        |
| `bias`  | Поправка игры к вендору: AMD в CoD и AC Shadows и т. п.                                      |

**Апскейл `U`** (Quality / Balanced / Performance):

| Разрешение | Quality | Balanced | Performance |
| ---------- | ------- | -------- | ----------- |
| 1080p      | 1.25    | 1.35     | 1.5         |
| 1440p      | 1.35    | 1.5      | 1.7         |
| 4K         | 1.45    | 1.65     | 1.95        |

- DLSS — только у RTX и только в поддерживающих играх.
- Если выбранная технология недоступна, берётся FSR или XeSS.
- Игра без апскейла считается без прироста.

**Поправки:**

| Поправка | Значение                                                                         |
| -------- | -------------------------------------------------------------------------------- |
| `M_ram`  | Двухканал — 1.0, одноканал — 0.85; DDR5 от 6000 — ×1.02, DDR4 ниже 3200 — ×0.97  |
| `P_vram` | `clamp((VRAM / нужно)^1.5, 0.3, 1)`. С апскейлом видеопамяти нужно на 10% меньше |
| `P_ram`  | ОЗУ меньше минимума игры — 0.7, меньше рекомендованного — 0.93                   |

**Генерация кадров:** 2× ≈ 1.8, 3× ≈ 2.6, 4× ≈ 3.3.

- MFG (до 4×) — только у RTX 50, у остальных — только 2×.
- Показывается отдельной строкой и не смешивается с «настоящими» кадрами.

**Лимит движка:** Elden Ring — 60 FPS. Ограничитель в этом случае — «лимит», диапазон
схлопывается до точного значения.

## Что показывает результат

- **Ограничитель:**
  - `FPS_CPU < 0.9 · FPS_GPU` — упор в процессор;
  - обратная ситуация — упор в видеокарту;
  - иначе — сбалансировано.
- **Диапазон** — ±15%. Вдали от эталонов — ±25%: индекс карты < 0.45 или > 2, процессора < 0.5.
- **1% low** ≈ λ · FPS: λ = 0.78 для AAA, 0.62 для киберспорта. При упоре в процессор — ещё −5%.
- **Цвет:**

  | Профиль    | Зелёный | Жёлтый | Красный |
  | ---------- | ------- | ------ | ------- |
  | AAA        | ≥ 60    | 30–59  | < 30    |
  | Киберспорт | ≥ 144   | 60–143 | < 60    |

  Пороги меняются для каждой игры в консоли.

## Обратный подбор («Хочу N FPS»)

`reverseFps()` подбирает три уровня сборки:

| Уровень   | Запас по каждой стороне |
| --------- | ----------------------- |
| Минимум   | ×1.15                   |
| Оптимум   | ×1.35                   |
| С запасом | ×1.65                   |

Запас нужен потому, что мягкий минимум при равных `FPS_GPU` и `FPS_CPU` даёт ≈ 0.87 от каждой
стороны.

Для каждого уровня:

1. Видеокарта: из наличия, по цене, с `FPS_GPU ≥ цель · запас` и без нехватки видеопамяти.
2. Процессор: по тому же правилу для `FPS_CPU`.
3. Остальные детали добирает тот же подборщик, что и у AI-консультанта (`composeAround`).
4. Сборка проверяется движком совместимости. Сначала берутся варианты без «бутылочного горлышка»
   по процессору, затем — самая дешёвая из подходящих.
5. Прямой расчёт перепроверяет, что прогноз не ниже цели.

Если цель недостижима, калькулятор так и говорит. Он подсказывает пресет ниже или апскейл, если
это помогает.

## Данные

| Таблица / ключ    | Что хранит                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------- |
| `games`           | Профиль, α, `bias`, требования к ОЗУ, поддержка DLSS/FSR/XeSS/FG, пороги, λ, лимит, обложка |
| `game_benchmarks` | `G` и требование к видеопамяти: 12 ячеек на игру                                            |
| `game_cpu_caps`   | `C`: 4 ячейки на игру                                                                       |
| `settings`        | Ключ `fps_model` — глобальный `k`                                                           |

**Seed** — 20 игр по плану (§13).

- Числа — стартовая оценка по сводкам публичных обзоров.
- Повторный seed **только добавляет** игры и не затирает правки из консоли и калибровки.

**Обложки** — CDN Steam (`steamAppId`).

- У игр не из Steam (Alan Wake 2, Valorant, RE Requiem, CoD MW4) обложка задаётся URL в
  консоли. Пока её нет — показывается градиент в цвете игры.

**Консоль → «Игры»** (админ и менеджер):

- правка всех параметров и сеток замеров;
- новая игра;
- импорт CSV: `game,resolution,preset,gpu_fps,vram_gb[,cpu_fps]`.

Строки с ошибками перечисляются с номерами, корректные применяются. Кэш калькулятора
сбрасывается, и новая игра сразу видна на `/fps` и в конфигураторе. Неполная игра (не все
16 чисел) в калькулятор не попадает.

## Калибровка

```bash
pnpm fps:calibrate                     # пробный расчёт по tooling/fps/data/control.csv
pnpm fps:calibrate путь/к/замерам.csv  # свои замеры
pnpm fps:calibrate -- --apply          # записать коэффициенты в базу
```

**Формат замеров:** `game,gpu,cpu,resolution,preset,fps`.

- `gpu` и `cpu` — ключи из `perf_gpu` и `perf_cpu`.
- Замеры считаются снятыми на 32 ГБ двухканальной DDR5-6000, без апскейла и генерации кадров.

**Что подбирается:**

- `k` из {3…8};
- для каждой игры — `α` и поправки встреченных вендоров: покоординатный спуск по сетке,
  минимизируется MAPE.

Игры, у которых меньше 4 замеров, калибровка не меняет: на 2–3 точках коэффициенты подгоняются
под шум.

**Текущий результат** (`tooling/fps/data/control.csv`, 68 точек):

| Метрика                           | Значение |
| --------------------------------- | -------- |
| MAPE до калибровки                | 5.7%     |
| MAPE после калибровки             | 4.0%     |
| Игр с подобранными коэффициентами | 9        |
| Цель плана                        | ≤ 15%    |

> **Важно.** Контрольные точки — **не замеры магазина**. Это приблизительная сводка по
> публичным обзорам, и её числа близки к тем же оценкам, из которых собран seed. Поэтому
> MAPE 4–6% говорит лишь о том, что модель и данные согласованы, а не о точности на реальном
> железе. Для честной проверки нужны собственные замеры (≥ 60 точек, по 4+ на игру) в том же
> формате. Тест `tooling/fps` проверит, что MAPE на них ≤ 15%.
