# Админ-панель (консоль)

## Доступ

- Консоль открывается только по секретному пути `ADMIN_BASE_PATH` (например, `/ops-7f3k2q`).
  `proxy.ts` переписывает его во внутренний маршрут `/<locale>/console/…` и помечает запрос
  служебным заголовком. Прямой адрес `/ru/console`, а также `/admin` отдают обычную 404 сайта.
  Ответы консоли — с `X-Robots-Tag: noindex, nofollow` и `Cache-Control: no-store`; в sitemap
  и robots путь не упоминается.
- Без `ADMIN_BASE_PATH` в продакшене консоль выключена. В dev и CI — запасной путь
  `/ops-console-dev`.
- Вход: логин сотрудника (`admin`, `manager`) и пароль. Двухфакторной защиты нет — пароль должен
  быть длинным и уникальным, а сам путь консоли — секретным.
- Блокировка: 5 неудачных попыток подряд → вход по этому логину закрыт на 15 минут.
- Вход (и сотрудников, и покупателей) и операции admin-плагина есть только в server actions:
  HTTP-эндпоинты `/api/auth/sign-in/*`, `/api/auth/sign-up/*`, `/api/auth/admin/*` отдают 404.
  Консоль пускает только роли admin/manager, вход на сайте — только покупателей: аккаунт
  сотрудника на витрине (и наоборот) получает ту же ошибку «неверный логин или пароль».

## Роли

| Раздел                                                               | Администратор | Менеджер |
| -------------------------------------------------------------------- | :-----------: | :------: |
| Дашборд, заказы и возвраты, товары, склад                            |       ✓       |    ✓     |
| Отзывы, промокоды, журнал платежей                                   |       ✓       |    ✓     |
| Пользователи и роли, настройки (курс, зоны, услуги), журнал действий |       ✓       |    —     |

Чужой раздел отдаёт 404 — без подсказки, что он существует. Каждое изменение (и каждый вход)
пишется в `admin_audit_log`: кто, что, над каким объектом, diff, IP.

## Демо-доступ (seed)

| Логин     | Роль          | Пароль                                                   |
| --------- | ------------- | -------------------------------------------------------- |
| `admin`   | администратор | `SEED_STAFF_PASSWORD`, по умолчанию `RedCore-Staff-2026` |
| `manager` | менеджер      | тот же                                                   |

Перед `pnpm db:seed` на продакшен-базе задайте свой `SEED_STAFF_PASSWORD`. Демо-покупатель для
входа на сайте: телефон `+998 90 123 45 67`, пароль `SEED_CUSTOMER_PASSWORD`, по умолчанию
`RedCore-Demo-2026`.

## Что внутри

- **Дашборд**: выручка (оплаченные заказы), заказы, средний чек, конверсия конфигуратора,
  графики по дням, топ товаров и сборок, воронка, заканчивающиеся товары. Определения KPI
  проверяются тестом против контрольных SQL-запросов.
- **Заказы**: фильтр и поиск, смена статуса по машине состояний (с комментарием), чек-лист
  сборки, возвраты по карте — полный или частичный, по желанию с возвратом товара на склад.
  Возврат уходит в Stripe с idempotency key `refund:<id>`, итоговый статус ставит вебхук
  `charge.refunded`.
- **Товары**: создание и правка. Форма характеристик строится из Zod-схемы категории
  (`specFormFields`), сохранение проверяется той же схемой, что и совместимость. Описания RU/UZ.
  Корректировка остатка с причиной; движения склада.
- **Отзывы**: модерация (публикация пересчитывает рейтинг товара). Покупатели оставляют отзывы
  на странице товара после входа; «покупка подтверждена» — если товар был в оплаченном заказе.
- **Промокоды**, **платежи** (попытки оплаты и события Stripe), **пользователи** (роль,
  блокировка), **настройки** (курс USD/UZS, контакты, зоны доставки, услуги), **журнал действий**.

Свою 3D-модель (GLB до 4 МБ) товару загружают на его карточке в консоли — см. [3D.md](3D.md).
